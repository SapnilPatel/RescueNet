# Demo script (~2 min)

**Setup before going on stage:** Render HQ awake (`/api/v1/health`), dashboard open on the laptop, Android beacon running with hotspot **SOS-HELP** on and mobile data off, QR code visible, iPhone 2 unmuted, backup video ready.

1. **"Towers are down. No internet."** (Helene: 74% of cell sites offline in the hardest-hit NC counties. Maui: cellular down, alerts never arrived.) The only network in the room is SOS-HELP.
2. **Judge's iPhone** joins SOS-HELP, scans the QR code, taps **Trapped**, types the location, 2 people, 1 injured → **Send**. The page shows the code and **"Saved on beacon — not yet delivered."** (We never say delivered before HQ confirms.)
3. **Teammate walks the Android across the room**, turns the hotspot off and joins Wi-Fi: "This is a fire truck driving out of the dead zone."
4. Within seconds: **pin on the HQ map**, card marked **CRITICAL** by rule triage (trapped + someone injured = critical) with a one-line summary → **iPhone 2 rings** (Retell reads the SOS aloud).
5. Dispatcher clicks **Assign → Engine 23, ETA 15**. The teammate waits one sync (~5 s), then walks back and turns SOS-HELP on again. The judge refreshes → **"Help is on the way: Engine 23 · ETA 15 min."**
6. Close on the **simulation chart**: "In a 16 km² dead zone with 300 trapped people, if 5% of phones carry our SDK and evacuating cars carry messages out, about 90% of SOS reach responders within an hour. At 2%, about two-thirds. Victims never install anything."

**Pitch close:** "Satellite SOS needs open sky. Mesh apps need you to install them before the disaster. RescueNet needs neither — you don't need our app to be rescued, but someone near you does."

## If something breaks
- HQ asleep/slow → keep talking through step 3; the upload retries automatically.
- Retell fails → play the recorded call.
- Beacon issues → backup video.
